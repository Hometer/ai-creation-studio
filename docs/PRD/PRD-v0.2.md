## 1. 目标用户与核心任务

### 1.1 延续的目标

首要用户仍为独立短片／短剧创作者。用户从灵感或剧本出发，建立角色与场景，组织分镜，生成和修改选定镜头，复用满意资产，最终预览并导出短片。

v0.1 的核心目标保持：对话式共创、统一资产库、指定镜头修订。版本、预算确认、任务恢复和成片导出为创作链路提供保障，新增辅助流程不取代核心目标。

### 1.2 第二版补充的问题

| 用户问题 | 本版收录的解决方向 |
| --- | --- |
| 不清楚两次文字修改之间到底变了什么 | 任意两版文字对比、版本来源与恢复前后定位 |
| 修改尚未正式应用，刷新后找不到草稿，或想找回旧稿 | 明确保存草稿、按修改请求查看和载入历史草稿 |
| 上游文字变化后，不清楚哪些镜头已检查、哪些仍需处理 | 持久人工核对记录；后续增加按恢复记录汇总核对进度的建议 |
| 希望保留文字副本，并在误改后找回正文 | 文字导出、备份检查、恢复预览、逐次确认及恢复记录 |
| 不容易分清当前正文、历史版本、草稿和备份 | 统一说明各自作用与保存状态，避免查看即覆盖或恢复即审核 |

这些问题的具体流程由执行者在开发过程中提出并细化；其中已获逐轮授权的部分已有代码。本版补记其需求来源，不将其伪装成首版原文。

## 2. 输入、过程与产物

### 2.1 继承的输入与产物

继承 v0.1 的文本、TXT／DOCX 剧本、图片、既有资产及 MP4 输入方向，具体上传规模和模型支持仍以技术适配及范围确认结果为准。首版建议验收样例仍为约 30—60 秒、3—6 个镜头，不在本次整理中擅自确认时长或镜头数。

最终核心产物仍为可预览、可下载的 MP4 成片，同时保留剧本、分镜、资产、候选版本、选用关系和任务记录。文字备份下载不等同于成片导出。

### 2.2 新增文字与记录输入

| 输入／记录 | 作用与边界 |
| --- | --- |
| 修改意图与保留要求 | 当前用户选择剧本／分镜的一处字段并记录原话；人工确认不代表模型已经理解或生成内容 |
| 人工修改草稿 | 保存候选文字，供继续编辑；不直接改变正式正文、版本或任务 |
| JSON 文字备份 | 用于检查及同项目文字恢复；目前只恢复其中当前剧本／分镜快照，不导入备份历史 |
| TXT 文字副本 | 供阅读和留存；当前不作为恢复文件格式 |
| 人工核对说明 | 记录继续使用或仍需处理的判断，并绑定当时核对依据 |

### 2.3 四种内容必须区分

| 内容 | 用户应理解的含义 |
| --- | --- |
| 当前正式正文 | 后续创作使用的当前剧本／分镜，修改须形成可追溯版本 |
| 已归档版本 | 当时正式内容的快照；查看不改变当前正文，回退需要独立预览与确认 |
| 修改草稿 | 尚未正式应用的候选内容；保存草稿与保存正式正文是不同动作 |
| 导出的文字备份 | 剧本／分镜及文字版本的副本，不包含完整项目媒体、任务或费用关系 |

下列建议纳入第二版候选池，当前均不承诺已实现。推荐顺序是先核对和完成核心创作链路，再判断辅助优化是否值得投入。

| 编号 | 建议 | 用户价值与拟定边界 | 当前状态／依赖 | 可核对的验收目标 |
| --- | --- | --- | --- | --- |
| O01 | 恢复记录的核对进度汇总 | 按一次恢复关联的变化版本，汇总未核对、仍需处理、有效继续使用、依据已过期事项，直接进入对应清单 | 待开发、待范围评审；已有版本限定清单是基础，不等于已有恢复汇总 | 多阶段恢复准确汇总，不混入其他恢复；过期结论不算完成；无影响事项不显示“审核通过”；汇总不自动保存、重生成或收费 |

## 4. 验收标准与异常处理

### 4.1 核心与新增流程的验收分开

核心业务验收仍按 F01—F08，使用 5—10 条有权使用的真实样例评估故事符合度、人物／场景一致性、指定修改效果、成片可用性、恢复可靠性及成本。效果阈值继续记为“待样例打分”，无真实调用不得写已通过。

N01—N10 的本地功能可用人工数据验证保存、查看、对比、输入保护和恢复一致性；人工数据必须标注。O01—O08 按批准范围分别验收，收录到 PRD 不算交付。

### 4.2 文字备份恢复的明确规则

1. 当前 JSON 备份只恢复同项目的剧本／分镜当前快照；TXT 仅供阅读。不同来源可检查范围，不允许借当前入口跨项目覆盖。
2. 检查和预览只读。确认恢复须对应本次文件、完整差异及当前正文；任一依据变化后重新预览和确认。
3. 两阶段正文、变化阶段的新版本及恢复记录一起保存；保留原历史和恢复前正文，不导入备份中的历史编号或旧授权。
4. 媒体、共创、计划、任务和费用不随文字恢复而自动重置。过期依据继续通过确定性检查处理，用户仍需核对关联内容。

### 4.3 公共异常规则

非法、失踪或重复地址参数应明确提示，不静默跳到其他版本或恢复记录。超限、坏文件、过期依据、执行中和存储不可读分别给出可执行提示；保留未保存输入及可保留的文件选择，旧结果不得继续作为有效确认依据。

模型未配置、调用失败或成本未知时保留已有成果；结构校验、超时及有限重试继续适用。高风险动作由确定性代码和人工确认约束，模型不能决定自动重做或新增费用。
