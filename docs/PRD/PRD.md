## 1. 目标用户与核心任务

### 1.1 产品背景

现有应用已形成剧本策划、角色与场景设计、分镜、参考图、视频生成和后期合成的六阶段流程，另有文艺短视频、动作迁移、数字人口播与临时工作台。

代码包含 Seedance 2.0、Kling V3、Wan 2.7 等模型配置，以及部分素材版本管理、参考输入和声音处理基础。当前模型密钥未配置，实际生成效果、模型可用性和费用均待真实验证。不能将接口或菜单存在视为该能力已经验收。

市场产品已进一步提供对话共创、资产复用、可视化导演控制、定向修改和商业内容生产能力。本项目拟在保留现有功能的基础上，改善创作过程的可控性与连续性。

本地项目 README 署名为 Innate Labs，目前未确认它属于字节官方小云雀的版本线。官方产品功能用于需求参考，不能假设可直接通过仓库升级获得。

### 1.2 首要用户与场景

**首要用户为独立短片／短剧创作者，产品经理已于本轮确认。**

典型场景为创作者已有一句灵感、故事梗概或简短剧本，希望生成一段人物和风格相对统一的剧情短视频，并能反复修改指定镜头、复用满意资产、保存创作过程。

品牌与电商营销团队、日常娱乐用户属于候选用户方向。若选择其一作为首要用户，需要重新调整核心流程和优先级，避免一个首版同时承担多个不同业务目标。

### 1.3 用户问题与产品目标

| 用户问题 | 首版拟解决的目标 | 用户可以感知的变化 |
| --- | --- | --- |
| 修改人物、台词或情节时，需要重复填写上下文 | 对话式共创 | 在项目内说明修改意图，看到明确修改范围和新版本 |
| 满意的角色和场景分散在生成记录中 | 统一资产库 | 为资产命名、选择版本，在镜头和新项目中明确引用 |
| 一段画面不满意，容易连带重做其他内容 | 指定镜头修订 | 只对选中的参考图或视频片段生成候选结果，保留满意部分 |
| 调用模型前不清楚会生成多少内容、花多少钱 | 可确认的生成计划 | 先看到生成对象、次数和费用估算，再决定是否执行 |
| 失败或重启后不知道做到哪里 | 创作过程可恢复 | 找回项目、确认点、任务结果和已选资产 |

## 2. 输入、过程和产物

### 2.1 首版输入建议

| 输入 | 用途 | 建议默认边界，待统一确认 |
| --- | --- | --- |
| 文本想法、故事梗概、剧本 | 生成或修改故事、分镜 | 首版优先短文本；单次最多 10,000 字，超出时提示拆分 |
| TXT、DOCX 文件 | 读取已有剧本 | 单文件最多 5 MB；解析失败时给出可执行提示 |
| JPG、PNG、WebP 图片 | 角色、场景、道具与风格参考 | 单文件最多 10 MB；按所选模型限制参考数量 |
| 已有项目资产 | 保持创作连续性 | 由用户选择明确的资产及版本 |
| MP4 视频 | 指定已有片段、保存和复用参考 | 单文件最多 100 MB；可处理时长与编码需在技术适配中核对 |

这些数值用于初版评审，依据是控制本地试用的上传与生成规模，不是现有系统已达到的性能承诺。音频上传、长剧本、超长视频、更多格式列入后续扩展。

上传素材只在用户选择用于生成时，进入相应模型调用；界面需要说明该次调用使用的厂商和素材范围。具体可用厂商与隐私边界待确认。

### 2.2 创作过程中的可见内容

- 项目目标，包括内容类型、故事、风格、比例、目标时长和参考资产。
- 剧本与分镜草稿，以及每轮修改的对象、原因和版本。
- 角色、场景、道具、图片、视频等资产的名称、版本和引用位置。
- 生成计划，包括处理对象、生成次数、所用模型、费用估算及可能受影响的后续产物。
- 任务状态，包括待确认、排队、执行中、成功、失败、取消和待恢复。
- 指定镜头的修改前后预览，以及用户最终选用的版本。

### 2.3 交付与保留

首版建议以一支约 30—60 秒、包含约 3—6 个镜头的短片作为真实验收样例。时长和镜头数是首版试用范围提案，需要产品经理确认；成片由多个片段组织而成，不要求模型一次直出。

最终产物为可预览、可下载的 MP4 成片，并保留剧本、分镜、选用资产、生成版本和创作记录。具体导出分辨率由真实可用模型决定，不承诺所有模型支持相同规格。

项目、任务、用户确认记录、资产文件及其引用关系必须持久保存；服务重启后仍能读取。保存期限与删除规则见第 7 节，尚待确认。

## 3. Agent 的主链路

### 3.1 推荐流程

1. **建立项目。** 用户输入故事或上传剧本，补充风格、比例和参考素材。Agent 复述理解，指出缺少的必要信息。
2. **共创剧本。** Agent 形成故事设定、简短大纲或正文。用户通过对话修改人物、冲突、节奏和台词，确认满意版本。
3. **确定资产。** 用户上传、生成或复用角色、场景和道具。用户确认本项目使用哪些资产版本。
4. **规划分镜。** Agent 拆分镜头，列出每个镜头的内容、引用资产、时长、画面与声音要求。用户可以单独修改镜头。
5. **确认生成计划。** 系统展示参考图或视频生成计划及费用估算。需要用户确认后才执行产生费用的调用。
6. **生成与审阅。** 逐镜头展示结果与任务状态；失败镜头单独处理，成功内容继续保留。
7. **定向修订。** 用户选中一个镜头或参考图，说明希望修改的内容和必须保留的要素，查看新候选版本并选择。
8. **合成与导出。** 用户确认片段和顺序，生成成片并下载；之后仍可回到项目继续修改。

继续保留现有六阶段流程及已有入口。新增能力如何接入页面，由后续技术适配确定；不得以升级为由直接移除现有工作方式。

### 3.2 首版功能需求

| 编号 | 功能 | 用户行为与系统要求 | 可核对的验收结果 |
| --- | --- | --- | --- |
| F01 | 项目与创作目标 | 新建、命名、打开项目，填写故事、风格、比例和目标时长 | 保存后刷新和重启服务，项目参数仍可读取 |
| F02 | 对话式剧本与分镜共创 | 用户围绕选定项目或镜头提出修改；Agent 展示修改对象和影响范围，提交后形成新版本 | 修改指定台词时，其余已确认内容保持；可查看旧版本并恢复为当前选用版本 |
| F03 | 统一资产库 | 上传或保存生成结果，为角色、场景、道具和素材命名，记录来源、版本及引用位置 | 同一资产可被多个镜头引用；用户可手动选入新项目，引用版本可追溯 |
| F04 | 镜头级参考控制 | 每个镜头可选角色、场景与参考图，编辑画面、动作和声音要求 | 镜头卡显示实际选用版本，提交内容与用户确认的计划一致 |
| F05 | 指定镜头修订 | 首版覆盖参考图定向编辑与指定视频片段重新生成；修改必须保留旧结果，提交前列明保留要素 | 新结果作为候选版本出现，用户选择后才替换当前片段；未选中的镜头和成片旧版本仍存在 |
| F06 | 版本与依赖提醒 | 对剧本、分镜、资产和视频记录修订；上游变化后标出受影响镜头，等待用户决定是否更新 | 改变角色服装后，只标出引用相关版本的镜头；不自动重做、不自动收费 |
| F07 | 生成计划与费用控制 | 显示模型、对象、数量和估算；由确定性规则校验预算、确认状态和执行次数 | 未确认计划不能执行；超出已设上限被阻止；估算与实际记录分开，未知费用不得显示为零 |
| F08 | 任务恢复与导出 | 保存任务状态、外部任务标识与确认点；展示失败和恢复入口；使用选用片段合成 | 重启后可找回待确认和已完成内容；外部任务未明确失败前，不重复提交付费生成 |

F05 的视频片段重新生成属于镜头级修订。直接在已有视频中替换背景、商品、人物或指定时间范围的像素内容，列为下一轮视频编辑能力，必须另行验证模型效果、保留程度与成本。

资产引用采用明确版本。资产库中创建新版本后，旧项目继续使用原版本，由用户决定是否升级；跨项目自动覆盖不属于首版。

### 3.3 人工确认与异常处理

| 情况 | 产品行为 |
| --- | --- |
| 信息不足或用户要求含糊 | 询问必要问题，或提出可编辑建议；不直接提交付费任务 |
| 未配置密钥、模型不可用或费用规则未配置 | 给出明确状态和配置入口，保留草稿与已有产物 |
| 请求产生费用 | 显示计划并等待确认；计划的对象、数量或费用增加时，需要重新确认 |
| 模型输出不符合约定结构 | 标记失败并按有限重试规则处理；不把错误内容保存为成功结果 |
| 超时、服务失败或任务状态未知 | 保留任务状态，允许查询或恢复；重试次数有上限，可能新增费用时按预算和确认规则处理 |
| 取消任务 | 尽量停止后续步骤，说明外部任务可能已在执行；保留已产生的结果与费用记录 |
| 上传文件无效 | 拒绝真实类型、大小或格式不符合要求的文件，不接受危险文件名 |
| 用户替换素材或回退版本 | 展示受影响内容，由用户确认后更新当前选择 |
| 删除项目或被引用资产 | 明示删除范围和影响，等待确认；不批量删除其他项目正在使用的资产 |
| 分享、发布或对外发送 | 首版仅下载成片；以后如接入发布服务，必须单独获得用户确认 |

## 4. 什么算“生成得好”

### 4.1 功能验收与效果验收分开

功能验收检查操作是否正确、状态是否恢复、费用是否受控、版本是否保留。模型效果验收检查故事、人物、镜头、修改结果和成片是否达到创作目标。模拟测试通过不能代替真实效果验收。

| 维度 | 初版评价要求 |
| --- | --- |
| 故事理解 | 保留用户明确要求的主题、主要人物、关键情节和结局；歧义先确认 |
| 对话修改 | 处理用户指定对象，能够说明修改了哪些内容；保持未请求修改的已确认文本 |
| 人物与风格一致性 | 同一角色、服装、重要道具和整体风格的偏差需在真实样例中评价 |
| 镜头表现 | 镜头基本符合确认后的分镜和参考要求，异常结果可被替换 |
| 定向修订 | 对“需要改变”和“必须保留”的要素分别打分，不承诺生成式修改天然精确 |
| 声画与成片 | 可正常播放，片段顺序符合确认结果；所选流程要求对白、声音时，单独验收 |
| 可恢复性 | 刷新或重启后项目、版本、选择、确认点与任务记录可恢复 |
| 费用与安全 | 没有未经确认的收费调用，不泄露密钥和完整用户文档 |

### 4.2 真实样例打分

生成效果的数字阈值记为 **待样例打分**。首轮选择 5—10 条有权使用的真实样例，覆盖从零创作、剧本修改、资产复用、指定镜头修订和失败恢复。产品经理对故事符合度、一致性、修改效果和可发布程度评分，并记录是否愿意使用以及原因。

根据这轮结果确定合格线、允许的瑕疵、可接受重试次数和成本，再评估是否需要调整模型或缩小需求。缺少真实密钥时，真实模型冒烟记为“待验”，不能宣布对应开发阶段完成。

轻微画面偏差的容忍度待确认。指定人物或剧情错误、丢失项目、无确认收费、泄露敏感数据、覆盖满意版本等问题不能作为可接受瑕疵。

## 5. 交付阶段与优先级

### 5.1 建议首版范围

首版建议提供本地单用户试用的 Web 工作台，围绕 F01—F08 跑通一条真实短片创作链路。首要能力为对话共创、统一资产库和指定镜头修订；版本、预算确认与恢复能力是这条链路的必要支撑。

这个范围尚待产品经理确认。用户规模、交付日期和开发工期未确定，工期在需求确认与技术适配后估算。

### 5.2 功能候选池

| 优先级提案 | 功能 | 本轮定位与依赖 |
| --- | --- | --- |
| P0 | 对话式共创、明确资产引用、指定镜头修订 | 首版核心能力，先做真实纵向验证 |
| P0 | 版本记录、预算确认、任务恢复、成片导出 | 核心链路的可靠性与验收要求 |
| P0 | 现有代码中影响验收的问题 | 纳入对应阶段修复，不能靠忽略错误通过检查 |
| P1 | 自由画布、时间轴和多轨声音操作 | 在核心链路验证后扩展创作工作区 |
| P1 | 已有视频定向编辑、连续延长、多模态参考输入 | 分别核验厂商能力、调用限制、编辑效果和费用；保留已有接口基础 |
| P1 | 低成本样片到高清成片的确认流程 | 确认存在适用模型及真实成本收益后再纳入交付 |
| P1 | 多镜头智能预演、完善的跨项目角色与场景管理 | 依赖稳定资产引用和镜头状态管理 |
| P2 | 动态 3D 导演台、空间与动作轨迹控制 | 独立评估交互复杂度、范围和工期 |
| P2 | 热点检索、参考视频拆解、创意方案助手 | 依赖可用数据源、合法素材和明确内容场景 |
| P2 | 商品广告、批量变体、视频翻译、营销分析 | 若首要用户改为营销团队，需重新评审并提升相应优先级 |
| P2 | 原片重制、白模复刻、短剧出海本土化 | 另行评估素材权利、目标市场、成本和完整制作链路 |
| P2 | 专属真人角色、声音身份复用 | 必须先明确肖像与声音授权、敏感信息处理规则 |
| P2 | 团队实时协作、公开分享、自动发布、插件与自定义技能 | 涉及账号、权限、外部连接与发送确认，另行立项评审 |

P1、P2 为候选池，不是本次首版交付承诺。新模型接入服务于已确认需求，不以接入模型数量作为验收标准。

### 5.3 按项目规则推进

| 阶段 | 主要产出与闸门 |
| --- | --- |
| 0 PRD 体检 | 确认初稿与补全清单，关闭影响范围、成本和隐私的待定项 |
| 1 技术适配 | 核对现有功能和数据兼容性，形成技术适配声明、模型验证方案与工期估算 |
| 2 后端 MVP | 分子阶段实现必要的持久状态与核心接口，运行 mock 测试及真实模型冒烟；用最小界面交付证据 |
| 3 正式前端 | 核心链路验证后完善工作台，检查桌面和手机操作，交付截图与验收步骤 |
| 4 上线 | 交付方式确认后提出上线方案，先确认费用，再创建付费资源；验证后端权限与数据恢复 |
| 5 收尾 | 更新运行、验证和交接资料，提醒删除或降权临时云密钥 |

每个开发子阶段单独交证据包和阶段闸门。真实模型未验、质量检查未过或证据缺失时，不宣布阶段完成。

## 6. 模型与成本约束

### 6.1 模型选择

默认推荐保留现有模型接口与选择能力，按真实样例决定首版采用的厂商和模型组合。是否允许境外模型、是否指定或禁用厂商，以及视频编辑所需模型，均待确认。

官方产品提供的功能不等同于其公开 API 可调用的能力。接入前核对 API 可用性、输入类型、时长、声音、分辨率和地区限制，再形成技术适配结论。

模型厂商、单次项目费用上限、每日或每月预算目前均未确定。PRD 评审及本地文档操作不调用收费模型；真实冒烟必须在预算与厂商确认后执行。

### 6.2 必要费用规则

- 生成前展示估算，并列明估算依据和不确定项；没有可用费用信息时不能将费用写为零。
- 用户确认对应的生成计划，确定性代码校验上限、次数和执行范围；模型不能自行提升预算。
- 估算费用与实际可取得的计费信息分别记录；厂商未提供准确账单时，明确标为估算。
- 因超时或进程重启导致结果未知时，优先查原任务，不盲目重复提交。
- 重试有上限，可能新增费用时需要符合既有确认及预算范围，否则重新确认。
- 批量生成、计划变化、使用更高费用规格等操作必须展示新的费用与数量。
- 云资源预算与模型预算分开；新增付费云资源前先提供费用量级并获得确认。

## 7. 数据与非功能要求

### 7.1 数据保留与隐私

| 数据 | 要求与初版提案 |
| --- | --- |
| 项目、文本、分镜、确认点和版本 | 持久保存，更新可追溯，回退形成明确的当前选用版本 |
| 资产与引用关系 | 保留来源、文件、版本和引用位置；删除前检查对其他项目的影响 |
| 模型与合成任务 | 保存任务标识、状态、计划、错误摘要和产物，支持恢复 |
| 费用记录 | 保留计划估算、确认范围和可取得的实际计费信息；不记录密钥 |
| 密钥 | 不进入代码、仓库、前端产物、日志、截图或提交记录；配置保存方式由技术适配按根目录规则落实 |
| 日志 | 记录定位问题所需的任务标识、状态和错误摘要，不记录密码、密钥或完整用户文档 |

建议试用期由用户主动管理项目和资产，不自动清除业务数据；临时文件的清理规则在技术适配中确定。业务数据留存期限、删除恢复窗口、备份位置与容量上限仍待产品经理确认。

是否涉及真人肖像、声音、个人信息或企业机密，以及数据是否必须留在国内，目前未知。未明确授权和数据边界前，真实测试优先使用公开且有权使用、无敏感信息的素材；不能把任何现有上传素材默认视为可发送给任意厂商。

### 7.2 可靠性与使用体验

- 建议首版支持 1 名本地用户、1 个主动生成的项目，保留多个项目记录；多用户和并发规模另行确认。
- 长任务不要求即时完成，但必须显示阶段、状态、失败原因和可执行的下一步，不虚构进度。
- 需要模型重试的错误与用户可修正的错误分开处理，处理超时、初始化失败和服务失败。
- 模型输出需结构校验；接口需定义请求、响应和错误，统一返回 `{"error":{"code","message"}}`，不向用户泄露技术堆栈；SSE 以 `done` 或 `error` 事件结束。
- 上传校验格式、真实类型、大小及安全文件名，不能仅检查扩展名。
- 后端检查资产与文件访问权限。进入任何多人共享环境前，验证用户只能访问自己的项目、素材和任务。
- 桌面与手机宽度均需验收；首版桌面优先，但手机不能出现关键操作被侧栏遮挡的情况。
- 现有项目、素材、任务和功能保留兼容；有迁移成本或客户端不兼容的替换必须先确认。
