# 资产与版本后端验证

日期：2026-10-04。开发文档先形成，再开发、验证和本地提交。本轮完成文字资产与指定版本引用的工程验证，整个阶段 2 仍待真实模型和业务验收。

## 可以核对的结果

- 角色、场景、道具可以人工建立文字资产；已有脚本角色、场景可显式导入，来源被保留。重复导入同一内容不会产生多余版本，内容变化会追加版本。
- 旧版不被覆盖，引用明确固定到版本。新版本仅提示有更新，升级或回退需要明确操作并记录历史。不同项目可引用同一资产；一个项目升级不会改变另一个项目的引用。
- 引用项目、片段、镜头必须存在；并发旧确认返回 409，重新查看后才能选择。目标被原流程移除后，历史保留并提示目标缺失。
- 实际结束隔离 HTTP 服务并重启，资产、两个版本、引用历史和原项目快照保持一致；重启后仍拒绝过期确认。写入失败、并发写入、损坏文件与符号链接均有测试。原有用户数据未修改。

## 照着点验证

先按 README 从根目录启动后端。浏览器打开 http://127.0.0.1:8000/docs ，向下找到“资产与版本”。点击某个接口后，点 `Try it out`，填请求框，再点 `Execute`；以 `Server response` 的状态和正文为准，下面静态的 `Example Value` 只是接口示例。

1. 点绿色 `POST /api/assets`，把请求框替换成下列人工角色，点 `Execute`。看到 201、`number=1` 算建立成功。保存响应中的 `asset_id` 与第一版 `version_id`。

```json
{"kind":"character","name":"验收小云雀","definition":"黄色羽毛，清晨送信"}
```

2. 点蓝色 `GET /api/assets`，依次点 `Try it out`、`Execute`，看到 200 和刚建立的角色。首次没有资产时返回空数组也是正常结果。
3. 点绿色 `POST /api/assets/{asset_id}/versions`，在 `asset_id` 填第 1 步的编号，请求框填下方内容。看到 201、两个版本，其中第一版仍为黄色羽毛，第二版 `number=2` 为蓝色羽毛，算追加成功。

```json
{"name":"验收小云雀","definition":"蓝色羽毛，人工第二版"}
```

4. 验证引用时，先在原前端新建一个人工故事项目，保存项目编号；停在待生成状态即可。这一步不要求执行生成。点绿色 `POST /api/asset-references`，请求框按下方填写，把三个“填……”换成实际编号，点 `Execute`。看到 201、`revision=1`、`has_newer_version=true`，算固定到旧版成功。只引用项目时不用填写 `segment_id` 或 `shot_number`。

```json
{"project_id":"填项目编号","asset_id":"填资产编号","version_id":"填第一版编号"}
```

5. 点 `GET /api/assets/{asset_id}/usage`，填资产编号后执行。看到第一版编号算没有自动升级。点 `PATCH /api/asset-references/{reference_id}`，填第 4 步返回的引用编号，请求框填第二版编号及 `expected_revision: 1`。看到 `revision=2`、两条 `history`、`has_newer_version=false` 算明确升级成功。再次沿用旧的 `expected_revision: 1` 执行会返回 409，提示重新查看后确认。
6. 在后端终端按 Control+C，然后使用同一启动命令重启；重新查询 `GET /api/assets` 和 `/usage`，看到相同资产、版本和历史算恢复成功。

上述手动操作会创建自己的本地验收记录。本轮没有资产删除接口；请先使用人工、非敏感样例。镜头引用仅支持实际存在的分镜位置，尚无分镜时使用项目级引用。

临时截图服务已停止；上述地址是按 README 启动后的本地地址。正式资产操作页面与模型生成输入接线留在后续切片。
