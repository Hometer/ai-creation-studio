## 在这台电脑照着核对

1. 在项目根目录的终端运行 `python3.12 scripts/project.py plan-demo`，看到“人工样例验收”及 8001 地址算启动成功。端口占用时先使用已有对应服务，或加 `--port 8002` 并替换下列地址端口；不会自动停止其他程序。
2. 浏览器打开 http://127.0.0.1:8001/api/project/media-demo/generation-plans ，勾选“美观输出”。应有保留的两个人工计划。费用字段 `cost.status` 是 pending_confirmation，amount／currency 是 null；execution_allowed 是 false。
3. 打开 [旧计划](http://127.0.0.1:8001/api/generation-plans/aa5b9447540a47c994deedeac0ab2e00)，勾选“美观输出”，看页面底部。确认仍保留，current=false，seg-1 的 reasons 包含 reference_changed；固定素材仍是 number=1。再打开 [新计划](http://127.0.0.1:8001/api/generation-plans/739ea1a6a47e49738b74ddcd9a37f49f)，应为 current=true、confirmed_local，固定图片 number=2。
4. 打开 http://127.0.0.1:8001/docs ，找到“生成计划（仅本地准备）”，展开 POST `/api/generation-plans/{plan_id}/dry-run`，点 Try it out。plan_id 填 `739ea1a6a47e49738b74ddcd9a37f49f`，点 Execute。Server response 应是 200；Response body 应显示 seg-1、5 秒、明确 first_frame_url，执行仍为 false。这里的 Execute 只发送本地 dry-run 接口，不生成视频。
5. 将 plan_id 改成 `aa5b9447540a47c994deedeac0ab2e00`，再次点 Execute。应是 409，错误 code 是 PLAN_SOURCE_CHANGED，提示查看影响后新建并重新确认。重复确认原计划也不能绕过变化检查。
6. 回到终端按 Control+C，等服务停止；再次运行 plan-demo，刷新两个计划并重做第 4、5 步，结果应一致。验收记录保留在根 `data/generation-plan-demo/`，不进 Git；不要删除目录或手工改 JSON。测试结束后按 Control+C 停止服务。

这些计划编号对应本机保留的人工记录，新电脑或不同数据目录须新建人工记录，不能拿截图编号当通用业务数据。若要从零复用，在 /docs 先通过 import-media 归档项目 media-demo、character_design、characters、role-1 的候选 1／2，再创建明确图片版本引用；Create Plan 填项目 media-demo、片段 seg-1、duration=5、model=local-test-model、mode=first_frame、该 reference_id 与 role=first_frame。查看返回内容后，Confirm Plan 填返回的 content_hash 和 local_only=true，再按新 plan_id 做 dry-run。该流程复用正式业务规则，没有模型调用。
