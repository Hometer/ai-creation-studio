# 图片与视频归档验证

日期：2026-10-04。先形成开发文档，再开发、验证与本地提交。本轮通过本地媒体归档的工程检查；整个阶段 2 仍待真实模型与业务验收。

## 已验证的行为

- 角色、场景、参考图和片段视频可从原项目已选素材或历史候选显式归档；兼容旧场景图片／视频映射。归档不改变原 `selected`，不触发生成。
- 文件复制成独立版本，保存真实格式、大小、尺寸、摘要与来源。重复归档相同内容幂等，变化追加版本；镜头保持旧引用，明确升级／回退记录历史。
- 图片由 Pillow 校验，视频由有超时、禁用网络协议的 ffprobe 校验；拒绝错误格式、超限、跨项目／越界路径、远端 URL 和符号链接。文件名由服务端生成，读取不接受路径参数，也不暴露原磁盘路径。
- 实际结束 HTTP 进程、删除人工原素材并重启后，归档 PNG、MP4、两个图片版本和镜头引用历史仍可恢复，二进制摘要相同，原项目快照不变。旧文字库继续可读。
- 失败提交不会留下指向缺失文件的版本；写入失败清理本次未提交副本，提交后才抛错时保住已提交副本。并发重复归档不会产生重复版本；文件损坏或缺失时返回安全错误，不返回错误字节。

## 照着点复核

从项目根目录按 README 启动 `python3.12 scripts/project.py media-demo`。打开 http://127.0.0.1:8001/docs ，看到标题“小云雀媒体归档 · 人工样例验收”算打开正确。服务使用独立人工数据，重启保留自己的验收记录；没有模型调用。

1. 找到“资产与版本”，点 `POST /api/assets/import-media`，点 `Try it out`，请求框替换为下方内容，再点 `Execute`。在 `Server response` 看到 200、`kind=image`、`number=1`、`mime_type=image/png` 算第一版归档成功。保存 `asset_id` 和 `versions[0].version_id`。若以前已归档，返回已有资产也是正常幂等结果。

```json
{"project_id":"media-demo","stage":"character_design","item_type":"characters","item_id":"role-1"}
```

2. 打开 `POST /api/asset-references`，填写下方内容，把“填……”替换成第 1 步编号。看到 201、`revision=1` 算镜头固定到第一版成功；若同一位置以前已有该资产引用，409 表示应该查询已有引用，不能重复新建。

```json
{"project_id":"media-demo","segment_id":"seg-1","shot_number":1,"asset_id":"填资产编号","version_id":"填第一版编号"}
```

3. 再执行 `POST /api/assets/import-media`，使用下方请求。看到同一 `asset_id` 下两个版本，第二版 `number=2` 算追加成功。首次验收按这个顺序操作；旧验收记录可直接用 `GET /api/assets` 查看历史。

```json
{"project_id":"media-demo","stage":"character_design","item_type":"characters","item_id":"role-1","candidate_number":2}
```

4. 点 `GET /api/assets/{asset_id}/usage`，填资产编号，点 `Try it out`、`Execute`。看到仍引用第一版并且 `has_newer_version=true` 算没有自动升级。需要升级时，使用 `PATCH /api/asset-references/{reference_id}`，填查询得到的引用编号，正文填第二版编号及当前 `expected_revision`；成功后历史增加一条。过期确认返回 409，需要重新查看。
5. 在浏览器地址栏打开 `http://127.0.0.1:8001/api/assets/填资产编号/versions/填版本编号/media`，分别替换第一、第二版编号。看到黄色和蓝色图片算两版均可读。也可在 `/docs` 的对应 GET 接口填写编号并执行。
6. 使用下方请求归档人工 MP4；看到 `kind=video`、`mime_type=video/mp4`、正时长，按第 5 步地址格式打开对应资产与版本，看到播放器算读取成功。

```json
{"project_id":"media-demo","stage":"video_generation","item_type":"clips","item_id":"seg-1"}
```

7. 在人工验收终端按 Control+C，再使用同一命令启动。重新执行 `GET /api/assets` 和 `/usage`，版本与引用历史仍在，媒体地址仍可打开，算人工入口重启恢复通过。数据位于根 `data/media-archive-demo/`；不用手工建目录或改文件。

正式应用启动后，以上归档接口也在 http://127.0.0.1:8000/docs ，使用实际项目编号和既有条目编号。此阶段未新增正式资产页面；归档不会驱动原生成流程自动采用新版本。临时验证服务均已停止，上述地址需启动后访问。
