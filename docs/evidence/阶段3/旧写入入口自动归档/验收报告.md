# 旧写入入口自动归档验收报告

日期：2026-10-05。先开发文档，再开发、验证和本地提交。本轮交付阶段 3 第 10 子阶段工程结果；真实模型、真机与业务仍待验，不能宣布整个阶段完成。

## 本次结果

旧通用补丁、工作流生成／介入结果及分镜逐集持久化文字快照，会自动追加剧本／分镜版本。第一次变化保留原基线，同次两阶段变化一并归档；相同快照、纯进度、参数和状态保存不新增版本。文字、历史和前后镜头影响在原会话文件中原子保存，版本来源沿用“原入口更新归档”。

保存失败、上限、缓存与磁盘冲突、损坏／未来结构均拒绝覆盖。任务期间文件变坏时，未提交文字也从内存回滚。原手动编辑和恢复不重复归档；自动版本可沿用恢复流程。原媒体选择／候选及人工记录保留，已有描述／时长同步继续生效。文字变化后，旧“继续使用”依据失效，需要重新核对。

后端最终 811/811（新增 32），前端 250/250，类型、Lint、生产构建通过。新增回归使用真实引擎与文件持久化，代理结果均为人工离线样例；原介入 HTTP 流按既有协议以 done 或 error 终止，没有供应商调用。A07、既有工具／SDK 警告继续保留。

实际 HTTP 先产生五条版本，重复补丁没有新增版本；浏览器恢复 v1 新增 v6，再由旧补丁产生 v7。人工核对确认保存一条“继续使用”，后一文字变化将其标为失效。真实服务停止重启后，七条文字版本、一条人工记录、三个接口响应及四个会话文件字节完全一致。原 167 个保护文件无改写、无缺失，主库五个项目可读。代码、文档、前端产物等超过 1400 个文件扫描，配置秘密匹配数与私有文件跟踪数均为零。

## 自己核对

1. 打开 [独立人工文字版本页](http://127.0.0.1:3006/projects/automatic-revision-demo/revisions)。看到“每次修改，都有来处”，版本列表有 v7、v6 与更早版本；这些都是人工样例。
2. 点击 v4 或 v3，看到“原入口更新归档”。点“预览恢复这一版”，核对修改前／后和受影响镜头；点“取消预览”保留现状。需要实际恢复时，先勾选确认，再点“确认保存新版本”；看到新增版本表示成功，旧版本仍在。
3. 打开 [人工核对页](http://127.0.0.1:3006/projects/automatic-revision-demo/reviews?item=f0e158126108fc3c4e9285c86da9b0860917ac1f90da2f167f91987b8fcda410)。选中的 v6 · seg-2 · 镜头 1 显示“依据已变化，重新核对”；往下查看历史人工记录，旧说明保留。
4. 要演练旧写入，打开 [人工 API 页面](http://127.0.0.1:8006/docs)，展开 PATCH /api/project/{session_id}/artifact/{stage}，点 Try it out；session_id 填 automatic-revision-demo，stage 填 script_generation，正文填 {"title":"人工样例的新标题"}，点 Execute。回文字版本页点“重新读取版本”，应新增一个版本；相同正文再提交不增加版本。只操作独立人工服务。

服务已保留。若后端停止，从根运行 `python3.12 scripts/project.py automatic-revision-demo`；若前端停止，另开终端从根运行 `BACKEND_API_URL=http://127.0.0.1:8006 npm --prefix /tmp/automatic-revision-frontend run dev -- --webpack --hostname 127.0.0.1 --port 3006`。数据在已忽略的 data/automatic-revision-demo/，与主库分开。端口占用时拒绝启动，不停止其他服务；该人工后端没有模型执行接口。

## 保留事项与下一步

任意两版直接对比界面、完整对话共创、实际重制作、真实预算与模型、worker、多用户、真机、业务验收和 A07 保持后续范围或待验。建议下一轮补任意两版文字对比，继续先文档、开发、验证、提交。本轮只做本地 Git 提交，不推送。
