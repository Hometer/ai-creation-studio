## 自己核对

打开 [第三轮可编辑人工草稿](http://127.0.0.1:3011/projects/comparison-demo/co-creation?intent=e336e6e43a0c4f47ac9e4965072733ca)，选择“第 3 轮 · 剧本”，向下找到“修改后的文字”。应显示之前保存的多行故事梗概草稿，“草稿已保存”；正文尚未应用。保存草稿不恢复预览和确认勾选。

1. 试改一句新文字，看到“有未保存的修改”，点“保存修改草稿”；成功后刷新页面，新文字应能找回。未点保存的文字仍只在当前页。
2. 改一句但先不保存，点“载入已保存草稿”，在提示中取消，刚才文字保持；再次载入并确认，才替换成最近草稿。
3. 点“预览这次修改”，核对前后文字、必须保留要求和影响。只有勾选“我已核对…”后，才允许“保存文字并关联请求”；这会改变人工演练正文，请确定希望保存后再点。
4. 第 1 轮已关联第 9 版，草稿仍保留；第 2 轮因正文依据变化，旧分镜草稿只供查看和复制，不能新保存或正式应用。第 3 轮有三份草稿，本轮页面只载入最近草稿，历史逐份选择待后续。
5. 两个窗口打开同一第 3 轮，一边保存新草稿，另一边基于旧记录保存会提示变化并暂停。点“重新读取草稿与版本”后，本页输入仍保留；手动载入前再核对最近草稿。

独立人工数据在根 `data/co-creation-draft-demo/`，全部为人工样例，不代表真实模型效果。当前独立前后端 3011／8011 与主生产预览 3000／8000 保留。服务停止时，根启动 `python3.12 scripts/project.py co-creation-draft-demo`；另一个终端进入 `/tmp/co-draft-frontend`，运行 `BACKEND_API_URL=http://127.0.0.1:8011 npm run start -- --hostname 127.0.0.1 --port 3011`（本轮独立构建已保留；临时目录丢失后的重新构建说明见 README）。不要把演练端口用于正式项目。

[空演练项目](http://127.0.0.1:3011/projects/revision-empty/co-creation) 与 [主生产空项目](http://127.0.0.1:3000/projects/edbbbd83281441849f7827d6cecca6cc/co-creation) 可只读核对，没有可选正文与请求时不显示可保存草稿。
