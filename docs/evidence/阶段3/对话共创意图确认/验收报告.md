# 对话共创记录与修改意图确认验收报告

2026-10-05，阶段 3 第 13 子阶段工程交付。遵循先文档、再开发、验证后本地提交，不推送。模型后置，真实模型、实体手机、业务及整个正式前端阶段继续待验，本报告不宣布阶段完成。

## 照着验证

1. 打开 http://127.0.0.1:3009/projects/comparison-demo/co-creation ，看到“先说清楚，再一起修改”和“本地记录 · 模型尚未接入”算对。右侧有五轮人工请求；不是模型回复。
2. 点“分镜”，修改对象选“seg-new · 镜头 1 · 台词”。在“希望怎样修改”填“让这句台词更坚定”，在“必须保留的内容”填“人物关系和其他镜头保持”，点“记录修改请求”。看到新一轮、原话、范围卡和待确认状态算对。
3. 核对对象、原文字和保留要求，勾选确认框，再点“确认修改意图”。看到“意图已确认”，原正文依然是原文字算对；这一步没有自动改写或生成。
4. 刷新页面，仍选中同一条请求，确认记录继续存在算对。点“撤回这条请求”，先取消可保留状态，再点并确认可撤回；原请求和已有确认时间仍在算对。
5. 空项目 http://127.0.0.1:3009/projects/revision-empty/co-creation 提示先准备正文；依据变化样例 http://127.0.0.1:3009/projects/manual-edit-demo/co-creation 点唯一请求，可见“依据已变化”，没有确认旧意图按钮。

入口已接素材页和文字版本页；“文字修改与版本”可继续原人工编辑闭环，本轮未把意图自动应用为正文。预览仅在本机。后端停止后根目录运行 `python3.12 scripts/project.py co-creation-demo`，默认 8009、独立 `data/co-creation-demo/`；前端独立副本命令见 README。临时副本清理后由开发者准备，不要求产品经理改文件。主应用 http://127.0.0.1:3000 已更新生产预览。

## 实际验证

真实本地后端与浏览器完成记录请求、确认、撤回和刷新恢复。确认框未勾选时按钮禁用；取消撤回不改变状态，确认撤回追加决定，原话不删除。剧本与分镜对象、意图、保留要求、正文依据和时间来自真实持久化接口。HTML 样例以纯文字保存／渲染，未执行。空项目不伪造对象或创建基线。

实际断网保存失败后，输入保留、写入暂停；联机后重新读取未发现原请求时仍保留输入，明确手动提交。真实 POST 已保存但人为丢弃浏览器回执时，只发一次请求；重读按 request_id 找回第三轮，清除对应草稿，没有重复记录。另一窗口真实保存导致当前依据过期，返回 409，原输入保留；另一次真实过期摘要也检查了安全提示。取消离开保留当前输入。读取挂起时重读和历史操作禁用，切换到空项目不带入旧项目记录。

独立 `manual-edit-demo` 先创建意图，再通过真实文字预览／保存接口人工改标题，旧意图立即显示依据变化且无法确认。该演练仅主动修改独立人工标题，其余人工正文／媒体保持；`comparison-demo` 的请求、确认、撤回不改变原文字或八条版本。没有模型或供应商调用，也没有费用、外发、任务执行或取消。

独立 HTTP 服务实际重启前后，两项目的共创、文字版本及 JSON 备份共六组响应逐字节一致，四个会话文件保持。主样例五条请求、三条决定完整恢复；另一个项目保留一条过期意图。原 199 个保护文件零改写、零缺失，主库五项目可读。旧入口自动归档、手动编辑与保存失败回滚均保留共创账本；发现磁盘上外部更新的合法账本时，旧写入拒绝覆盖。

390／768／1280／1440 宽度的控件在屏幕内、无横向溢出；390 可操作核对框、确认和撤回。主应用最终生产构建的 1440／390 空项目页面已查看。独立服务重启后的正常页面刷新未发现 Console 错误或失败网络请求。宽度模拟不代表实体手机验收。
