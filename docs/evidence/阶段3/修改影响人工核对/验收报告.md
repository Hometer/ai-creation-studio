## 自己打开检查

[人工核对页](http://127.0.0.1:3005/projects/impact-review-demo/reviews)；[原分镜页](http://127.0.0.1:3005/?session=impact-review-demo&stage=storyboard)；[文字版本页](http://127.0.0.1:3005/projects/impact-review-demo/revisions)。8005／3005 使用独立 data/impact-review-demo/；文字、素材引用说明和决定是人工样例，不代表模型生成或效果验收。主工作室仍在 http://127.0.0.1:3000 。

1. 打开人工核对页，在“核对清单”点一项。应显示修改版本、受影响片段／镜头和当前文字。展开“查看这次修改的全部差异”，可核对前后；相关内容入口可单独打开。
2. 在“核对决定”选择“仍需处理”或“已核对，继续使用”，在“核对说明”填写检查结果。点“核对决定并保存”只打开确认；未勾选时确认保存禁用。勾选后点“确认保存核对记录”。
3. 刷新，应保留人工记录、日期和决定。“仍需处理”继续计入待处理；继续使用只表示当时的人工判断，不批准执行或触发制作。
4. 从“文字版本与恢复”修改文字并确认，回核对页重新读取。原继续使用结论应提示“依据已变化，重新核对”；历史记录仍保留。镜头已移除或无法唯一定位时，继续使用不可选。
5. 失败时说明与已读清单保留，提示就在输入旁。先复制需要保留的说明，再点“重新读取核对记录”，确认放弃当前草稿，核对真实保存结果后继续；不会自动重发。

目前主人工项目四条文字版本、五项影响、四条人工记录：先保存继续使用；实际保存后丢弃浏览器回复，记录仍需处理；第二客户端保存继续使用；实际新增分镜修改使旧结论失效；再复验实际 201 回复丢失，追加仍需处理。两个断线草稿及并发旧草稿未落盘。当前五项仍待处理，可继续按上面步骤操作。

## 实际核对结果

- 事项按修改版本保留独立来源，来源差异每版只传一次；当前目标文字、存在／不唯一状态来自真实会话。人工记录追加留存，与正文、阶段产物、项目素材引用／资产版本、计划及文字历史绑定。后端在共用引擎／素材锁下重新校验依据、运行状态与目标。
- 自动回归覆盖两种决定、文本／媒体／引用／资产版本／计划变化、文字恢复后的保守失效、移除及重复目标拒绝继续使用、同编号幂等及改内容复用拒绝、旧依据冲突、协议类型与明确确认、损坏记录／计划、外部磁盘改写与原子写失败。核对保存保持原正文／媒体；没有任务、预算、计划确认或执行许可写入。
- 浏览器完整保存与刷新通过。两次真实 POST 201 后故意丢弃浏览器回复，各一次 POST、各只追加一条记录；说明保留且保存冻结，主动读取恢复真正持久化结果。没有用假成功接口冒充已保存。
- 两次浏览器断网确认保存均未新增记录，说明保留并冻结；恢复网络与主动读取成功。第二客户端先保存，旧页面确认返回 409、保留草稿且不覆盖；读取后显示第二客户端实际决定。
- 取消链接离开与浏览器返回保留草稿，主动读取前明确确认放弃。实际新增分镜文字版本后，原继续使用结论显示重新核对、保留旧记录；之后记录仍需处理，继续计入待处理。
- 390／768／1280／1440 原清单／表单与确认弹窗检查通过，长说明独立滚动，确认按钮均可见且未勾选禁用；手机卡片、触控与键盘确认可操作，页面无无意横向溢出。错误自动定位距页面顶部约 80px，避开固定顶栏。最终截图等待外壳响应式状态稳定后复查。
- 人工空项目、生产主库空清单、缺失项目安全错误与文字版本页入口通过；生产空页面四宽度无溢出。主库五个项目及新增核对工作区可读。原主库没有已完成文字，不新增模型结果充当核对验证。
- 最终后端 779/779（新增 28），前端 250/250（新增 26）；类型、零警告 Lint、生产构建通过。首次两项既有 HTTP 测试超时，单独复验 2/2、最终完整 779/779 通过；没有修改超时标准、删测试或屏蔽错误。原 pytest 配置与 DashScope 上游警告保留。
