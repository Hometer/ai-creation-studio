# 阶段 2 第 3 子阶段：图片与视频资产归档

日期：2026-10-04。本文先于本轮代码形成。产品经理已同意上一轮提出的图片／视频归档切片，并要求继续先文档、再开发、验证后提交。

## 交付范围

将现有角色图、场景图、分镜参考图和片段视频显式归档到资产库。默认归档当前 `selected` 素材，也可按候选序号选择既有 `versions` 中的历史素材。归档保存独立副本、真实格式、大小、尺寸、SHA-256 摘要及原项目／阶段／条目来源；原文件被后续流程修改或移除时，归档版本仍可读取。

同一项目、阶段、分类、条目对应一个媒体资产；再次归档相同内容与定义幂等，有变化时追加版本。项目、片段或镜头引用沿用上一轮的明确版本选择、升级回退历史和并发确认。归档、选择不会修改原项目 `selected`，也不会发起重新生成或收费调用。

本轮是本地后端切片，以 `/docs` 和媒体读取地址验收；不铺开正式前端。不新增任意文件路径导入、外网下载、素材上传、账号、云资源或数据库迁移。后期生成输入接线、费用确认和真实模型质量继续另行开发；Q2—Q5 的完整范围、预算、隐私和交付问题保留待定，本轮测试只用人工非敏感素材。

## 技术适配与兼容

沿用 FastAPI、Pydantic、现有 Pillow 与本机 ffprobe，不新增 Python／前端依赖。文字资产与引用接口继续可用；`kind` 增加 image/video，文字建档请求仍只接受 character/setting/prop，防止建立缺少文件的媒体资产。版本增加可选 `media` 信息，旧文字库不需迁移；`schema_version=1` 保留，未来不兼容结构必须另行设计版本迁移。

在原私有 `backend/data/asset-library/` 下增加 `media/`。元数据继续原子替换并使用同一进程间锁；临时副本校验后，以服务端随机文件名发布，再提交元数据。提交失败删除本次尚未引用的副本，不碰用户文件或已提交版本。若进程在文件发布后、元数据提交前结束，可能留下无引用副本；不会产生指向不存在文件的已提交版本，也不自动删除未知文件。该清理与磁盘配额功能以后单独设计。

媒体文件按版本单独存储，不能覆盖；文件与目录同步落盘。没有删除接口。重启后从磁盘恢复版本和引用，读取时核对文件大小与摘要。库与媒体不挂到 `/code` 静态目录，受控 GET 路由使用资产／版本编号查找，不接受客户端路径。当前仍限本机试用，正式多人服务需后端权限隔离。

## 格式与文件安全

采用本轮本地默认上限：图片 10 MiB，MP4 视频 100 MiB。图片支持 JPG/JPEG、PNG、WebP、BMP，以兼容原流程已有格式；用 Pillow 检查实际格式、扩展名匹配、解码完整性及最大 4000 万像素。视频只支持 MP4，检查容器签名，并以有超时、禁用网络协议的 ffprobe 校验实际容器、视频流、尺寸和有限正时长。格式不符返回 415，超限返回 413。

素材来源仅从指定项目的已保存产物中解析，且实际文件必须位于该项目对应的 `result/image/{project_id}` 或 `result/video/{project_id}` 子树。拒绝不存在或不唯一条目、缺少选择、任意 URL、跨项目路径、越界符号链接、非普通文件。读取有字节上限，不以客户端扩展名或声明类型代替真实格式检查；错误和日志不回显路径、素材正文或工具 stderr。输出文件名完全由服务端随机编号与校验后的格式确定。

## API 合同

沿用统一 `{"error":{"code","message"},"detail":"兼容字段"}`，OpenAPI 定义成功与错误响应。

| 方法与路径 | 请求与响应 |
| --- | --- |
| POST /api/assets/import-media | project_id、stage、item_type、item_id、可选 candidate_number（从 1 开始；不填为 selected）；返回 Asset，200 |
| GET /api/assets/{asset_id}/versions/{version_id}/media | 成功返回已校验格式的二进制，带 Content-Type、ETag 摘要、nosniff、private/no-cache；无文件路径参数 |
| 原资产查询与引用接口 | 响应媒体版本增加 media 信息；创建／升级引用继续校验真实目标和明确版本，原有接口保持可用 |

stage/item_type 只允许 character_design 的 characters/settings、reference_generation 的 scenes、video_generation 的 clips；兼容旧产物 scene_images／video_clips 映射。来源为 artifact，保存 project_id、stage、item_type、item_id，不暴露原磁盘路径。media 保存 file_id、mime_type、sha256、byte_size、width、height、可选 duration；同一资产的版本必须与 image/video 类型一致。不能给媒体资产通过文字版本接口添加无文件版本。

错误：422 请求结构／候选序号错误，404 项目／条目／版本不存在，409 没有可归档选择或不支持文字方式更新媒体，413 超限，415 格式错误，503 文件校验工具不可用／超时、持久化失败、归档文件缺失或完整性异常。原有 409 引用并发确认合同保持不变。
