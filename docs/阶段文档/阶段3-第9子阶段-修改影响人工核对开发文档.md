# 第 9 前端子阶段 · 修改影响人工核对

2026-10-05。依据产品经理继续授权，先形成本文档，再开发、验证和本地提交。上轮原编辑入口提交 bb435a9。本轮延续本地单用户与模型后置，不新增平台或费用。

## 目标与适配

文字修改后，创作者能按修改版本查看受影响镜头、核对当前分镜及后续素材，记录“继续使用”或“仍需处理”，刷新和服务重启后可继续查阅。沿用 Next.js 16／React 19、TypeScript strict、现有深色设计和原生控件，不迁移技术栈或添加依赖。新增独立核对页，文字版本页与原编辑成功提示提供入口。

## 范围与产品规则

- 每个修订版本的片段／镜头形成独立事项，避免历史汇总去重丢失来源。展示修改版本与原因、当时差异、当前可核对文字、存在／已移除状态，提供分镜、参考图、视频、后期、素材与计划入口。
- 人工记录追加留存，选择“已核对，继续使用”或“仍需处理”，填写 1—1000 字说明并明确确认。后者始终计入待处理；前者只在记录绑定的当前项目正文／阶段产物、项目素材引用与资产版本、生成计划及文字历史没有变化时有效。保守失效，回退文字也须重新核对。
- 已移除或无法唯一定位的镜头不能标记继续使用，只能记录仍需处理。服务运行中禁止写核对。没有已归档影响时显示真正空状态；未归档更新明确提示需要先归档。
- 核对不会重生成、删除、替换素材，不会更新任务、预算、阶段确认、计划有效性或执行权限。“仍需处理”是可恢复的人工待办记录，实际重新制作继续通过原入口单独操作。
- 原模型调用、旧介入／通用补丁逐次归档、完整对话共创、真实计费、worker、多人权限和上线保持后续范围。无法补回未记录的历史。

## 接口与持久化

- GET `/api/project/{project_id}/content-revisions/reviews` 返回 project_id、token、running、untracked_stages、事项与追加核对记录。修改来源 sources 单独返回差异，避免每个镜头重复传输整段结构。事项含 item_id、version_id／number／stage、目标、原因、来源差异、当前可核对字段、target_exists、pending／follow_up／retained／stale 与最新记录。token 绑定当前核对依据和完整记录。
- POST 同路径，必填 expected_token（64 位摘要）、item_id（64 位摘要）、decision（retain／follow_up）、note、request_id（32 位）、acknowledged=true。201 返回 review_id 与最新工作区；相同请求编号及内容幂等，改内容复用编号 409，历史请求重放不复活过期结论。
- 错误统一 `{"error":{"code","message"}}`；404 项目／事项不存在，409 依据变化／执行中／目标移除，422 输入／上限不支持，503 文件损坏／持久化失败。前端 20 秒超时，无自动重试；写入结果不明或冲突冻结表单，保留说明，主动读取核对后再操作。
- 核对记录使用会话文件新增可选字段 content_reviews，原子保存并在失败时还原内存，兼容缺字段旧会话，无迁移。和正文共用引擎锁；素材引用／计划共用既有 POSIX 库锁。读取校验整个项目产物与核对账本的磁盘／内存一致性，损坏拒绝覆盖。历史限 2000 条／8 MiB，事项限 1000，工作区响应限 16 MiB，明确拒绝、不截断。
- 依据仅保存摘要，不写密钥、完整项目文档或媒体副本；人工说明属于业务记录，不打印日志。浏览器不获得秘密。

## 状态与交互

| 状态 | 展示与操作 |
| --- | --- |
| 加载 | 读取状态，尚不显示空清单 |
| 空 | 没有已归档影响，入口回文字版本 |
| 待核对／过期 | 明确来源和下一步，可重新记录 |
| 仍需处理 | 说明与历史保留，计入待处理 |
| 继续使用 | 当前依据下的人工判断，明确不等于执行批准 |
| 运行 | 可读，写入禁用 |
| 确认 | 指定事项、决定、说明及边界，勾选后提交 |
| 失败／断线 | 保留表单与已读清单，冻结未知结果，主动读取恢复 |

URL 保存事项选择；新说明为临时草稿，取消、切换或离开须确认，提交中锁定。原生确认弹窗键盘可达。手机卡片、长文字折叠与换行、44px 操作、四宽度无意横向溢出检查。核对历史显示日期与是否仍适用，不靠颜色表示状态。
