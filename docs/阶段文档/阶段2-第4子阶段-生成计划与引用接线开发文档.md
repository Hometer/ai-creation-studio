# 阶段 2 第 4 子阶段：生成计划与素材引用接线

日期：2026-10-04。本文先于本轮代码形成。依据初版 PRD F04、F06、F07，以及技术适配声明与前三轮切片；产品经理已要求继续，仍按先文档、再开发、检查后提交。

## 目标与范围

本轮打通本地链路：已有分镜片段 → 明确选择资产引用及输入角色 → 保存生成计划 → 预览参数和待确认费用 → 确认本地内容 → 校验归档文件并准备视频客户端入参。生成单位沿用原应用的 segment，一个片段可以包含多个 shot；展示这些镜头，不偷偷改变原应用的生成粒度。

支持首帧、首尾帧、参考图三种已有输入形式。文字引用用于提示词上下文，图片引用明确分配为 first_frame、last_frame、reference_image；不靠名称猜角色图、不选择最新文件、不用下一个片段自动补尾帧。视频资产仍能归档，但本轮不是视频续写输入。原六阶段、原 selected、原付费路由和用户数据不改行为。本轮新计划没有执行模型的接口，确认只批准本地输入准备，不能作为支付或素材外发授权。

Q2—Q5 的全量范围、厂商／预算、隐私／留存与交付方式仍待定。本轮不需要 Key、不新增外部服务与依赖、不创建云资源，不做正式前端。客户端填的模型标识只用于本地参数预览，不代表厂商已支持或已完成真实验证。

## 技术与目录

沿用 FastAPI、严格 Pydantic、现有工作流快照、资产库与媒体 SHA-256 校验。新增 `api/schemas/generation_plans.py`、`core/generation_plans.py`、`core/generation_inputs.py`、`api/routers/generation_plans.py`，业务规则在后端复用。

计划保存在私有 `backend/data/asset-library/generation-plans.json`，不在 `/code` 或 Git。保持原 `library.json` schema 1 不变；计划文件独立 schema 1，以原资产库锁串行化计划和引用修改，并用原子替换保存。计划文件损坏、重复 JSON 字段、未来版本、摘要不符、链接或写入失败返回安全 503，保留旧数据。计划文件缺失才作为空库，不把损坏数据当新库。

仍限本地单工作流写进程；工作流快照锁与资产锁按固定顺序获取，资产锁可跨本机进程。确认与输入准备分别检查当时快照，后续真正执行必须再次校验并纳入持久化任务与费用约束。未来多人、分布式、关系事务或不兼容 schema 要单独适配与迁移，不为本轮重构已工作的工程。备份需保留会话目录和整个资产库目录。

## 数据与状态

请求明确项目、1—20 个不同片段、每片段 1—60 秒整数时长和最多 20 个不同引用。参数包括模型、三种模式、画面比例、分辨率、声音、镜头类型、风格。时长、模式参数不由模型决定；本地限制不替代未来厂商能力校验。

计划固定不可编辑的内容与 SHA-256：项目、参数、片段、镜头摘要、原片段摘要、最终提示词、每条引用的 revision／位置、资产与版本编号、完整版本定义／媒体摘要。计划正文不能携带客户端路径。修改计划只能新建，不覆盖已确认计划。确认记录保存时间、内容摘要、`local_input_only` 范围；重复确认幂等。

状态为 draft 或 confirmed_local。读取时计算每片段变化原因：片段消失／变化、引用消失／位置或 revision 改变、归档版本元数据变化。任何变化禁止确认或准备输入，返回 409；保留原计划，用户看差异后新建计划。资产仅新增版本时，仍引用旧版本并提示有新版，不自动失效或升级；明确切换引用（包括回退后 revision 变化）才要求重新确认。

费用始终返回 `status=pending_confirmation`、`amount=null`、`currency=null`，不把未知费用写成零。`execution_allowed=false` 固定，明确列出报价、模型／隐私与执行能力待接入。确认请求必须声明只确认本地内容且提供预览摘要，防止陈旧页面批准不同内容；这不是完整费用审批。

## 输入与 Prompt

Prompt 独立模块、模板版本 1：风格、明确绑定的文字定义、片段原有 shots 的 content 和 duration、禁止字幕／水印。分镜需有可读镜头内容与有效镜头编号；本地计划不隐式读取旧视频描述覆盖，不声称原流水线已按新计划运行。

引用必须属于该项目，位置为项目、该片段或该片段有效镜头；镜头引用保留来源位置，但对所在片段的单次生成生效。context 只接受文字资产，图片输入只接受图片资产。首帧模式恰好一个首帧；首尾帧模式各一个且不允许缺尾帧回退；参考模式 1—4 张明确图片（本轮本地上限）。重复引用、错类型、跨项目／片段、无效镜头拒绝。

输入适配器核对固定版本与媒体文件的大小／SHA-256，把确认计划转为现有 `VideoClient.generate_video` 的 prompt、image_path、last_image_path、reference_image_paths、model、duration、sound、shot_type、video_ratio、resolution 参数。调用方未来单独安排 save_path；本轮不实例化 VideoClient、不调用 SDK、不创建输出视频。内部文件路径只在后端适配结果中使用；公共 dry-run 返回受控媒体 URL 和固定参数，不暴露磁盘路径。真实执行前仍需价格、预算、隐私、模型能力、超时／有限重试和持久化任务。

## API 合同

统一错误沿用 `{"error":{"code","message"},"detail":"兼容字段"}`，每个接口定义请求、成功和错误响应。都是有界本地操作，无模型长任务或 SSE。

| 接口 | 合同 |
| --- | --- |
| POST /api/generation-plans | project_id、options、targets（segment_id、duration、bindings 中 reference_id 与 role）；201 返回 PlanView |
| GET /api/project/{project_id}/generation-plans | 返回该项目 PlanView 列表；不存在项目仍保留已存历史，不自动删除 |
| GET /api/generation-plans/{plan_id} | 返回固定内容／摘要、确认状态、费用待定、每片段影响与新版提示 |
| POST /api/generation-plans/{plan_id}/confirm | content_hash、local_only=true；仅当前计划可确认，200 返回 PlanView，重复幂等 |
| POST /api/generation-plans/{plan_id}/dry-run | 无请求正文；已确认且未受影响才校验文件并准备入参，200 返回 PreparedPreview；execution_allowed 固定 false |

错误包括 422 严格请求结构，404 项目／片段／引用／计划不存在，409 角色组合／引用范围／分镜内容无效、未确认、摘要不一致或来源变化，503 存储不可用／损坏或归档媒体完整性异常。不回显原文、文件路径、请求值或工具异常。
