## 范围与流程

用户从当前项目的文字版本页选择已有 JSON 文字备份，明确点“检查这份备份”。后端只读检查后显示来源项目、大小、格式版本、两阶段文字字段数量、当前内容是否与本项目相同、未归档状态及全部版本的时间／来源／恢复关系。不同来源项目允许检查，但明确标出来源不同；校验通过只表示当前格式及内部结构一致，不代表来源可信或已经恢复。摘要不是数字签名，文件内容与摘要一起被改动仍可能通过。

文件仅送到本机后端，不落盘、不写会话／正文／历史／媒体／计划／任务，不发往模型或云服务。没有应用／覆盖／删除按钮，不生成恢复授权。TXT、原会话 JSON、媒体与任意其他结构拒绝；现有文字导出与人工修改流程保持。检查结果是临时只读展示，刷新需重新选文件检查，不将上传内容或报告放入 LocalStorage。

## 接口契约

POST `/api/project/{project_id}/content-revisions/import-precheck?expected_token=当前文字摘要&filename=安全文件名`，请求正文是 JSON 文件原始字节，Content-Type 为 application/json。文件名必须是安全 basename 且以 .json 结尾，最多 128 字，拒绝路径／控制字符；真实类型由严格 UTF-8 与 JSON 内容决定。前端和后端都限制 64 MiB，后端流式限长，不信任 Content-Length。拒绝重复 JSON 键、NaN／Infinity、过深结构、未知版本、额外顶层字段、错误摘要、异常版本序号／恢复关系／当前版本引用／未归档标记。沿用每快照 2 MiB、每阶段 500 可编辑字段和历史 32 MiB 上限；深度最多 64、整个文档最多 500000 个节点，超限拒绝而不截断。

返回严格报告：project_id、token、mode=read_only、source_project_id、same_project、file_bytes、file_sha256、schema_version=1、两阶段摘要（字段数、历史数、与当前是否相同、是否未归档、归档版本引用）、版本摘要（编号／阶段／来源／日期／恢复关系／字段数）。不返回用户整份文档，不保留上传文件。原文件 SHA-256 由前端核对，保证报告对应所选文件。后端在检查文件后按 expected_token 再读取本项目文字，409 表示目标变动，先重新读取版本再检查；文件的旧 token 不要求等于当前项目 token。

错误沿用 error.code/message：404 项目不存在；409 当前文字依据变化；413 文件大小上限；415 文件名或真实类型不支持；422 格式／内容／关系／容量不符；503 原项目存储不可读。错误不包含文件内容／内部堆栈。前端 20 秒超时，不自动重试；手动重试同一文件是只读、无新增记录。鉴权沿用本机单用户边界，不冒充正式多用户隔离。

## 状态与保护

| 状态 | 页面行为 |
| --- | --- |
| 初始／无文件 | 说明 JSON／64 MiB 与本机只读边界，检查按钮禁用 |
| 选文件 | 清掉旧报告，显示文件选择，不自动上传 |
| 检查中 | 单次锁定文件与按钮，明确等待，允许页面其他流程保留 |
| 成功 | 来源与两阶段范围、版本摘要；无写入按钮，明确尚未恢复 |
| 失败／断线 | 清掉旧报告、保留所选文件；明确手动重试，零自动重发 |
| 当前工作区变化／卸载 | 忽略旧请求回执并清除报告，文件选择保留，重新检查 |
| 有编辑草稿／预览 | 检查不改编辑输入、预览或勾选，不触发放弃确认 |
| 刷新／返回 | 重新读取真实项目；文件和报告不持久化，需重新选择 |

## 风险与后续

只读报告不等于可安全覆盖项目；跨项目映射、恢复预览／确认／原子追加、共创关系及媒体引用恢复另阶段评审。当前只检查现有文字快照范围，完整项目备份仍需保留会话与资产库。文件在浏览器内存和后端请求内存中处理，不保存；解析深度／节点／大小限制减少大文件风险。原服务不可用时保留本页编辑与文件选择，服务恢复后重新检查。
