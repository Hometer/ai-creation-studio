# 阶段 2 第 8 子阶段：报价、预算与样例审核接线

日期：2026-10-04。本文先于本轮代码形成。基线 08e0eb3：后端 377 项、前端 33 项通过。用户授权继续，仍按先文档、再开发、验证后本地提交执行。

## 目标与范围

为固定万相生成计划关联人工录入的价格依据、单次／日／月额度、逐计划素材审核和持久化准备记录。报价、额度与素材确认形成可核对的摘要，变更后失效；准备记录具有幂等请求编号和本地额度分配，重启保留。任何金额未知均为 null，不当作 0 元。

沿用“不收费调用、万相准备、有权非敏感素材境内处理”。本轮不为用户确定实际价格或额度；无 Key、无模型请求、无素材外发、不创建云资源。人工记录不是平台认证或账单证据；全程 real_execution_allowed=false，account_price_verified=false。只允许准备确认，不允许付费执行确认。真实联网 transport、实际计费／结算、后台 worker、正式前端和多人权限继续暂缓。

## 技术适配与边界

沿用现有 FastAPI、严格 Pydantic、计划／资产共享锁、read_document、atomic_write_session、目录同步，不增加依赖或替换旧文件。新增 schema 1 generation-readiness.json，保存不可变价格／预算版本、报价、审核、准备记录及当前版本指针；旧 SIM 账本、离线协议演练、预检历史与资产来源合同保留。当前仍限本机单工作流写进程，文件锁覆盖读改写；未来多人事务存储另行适配。

价格来源分 manual_account（用户声明来自账户、未独立验证）与 offline_fixture（人工演练）。价格绑定一个明确模型标识，分别录入 720P／1080P 的整数分／秒，设置有效期；不硬编码官方原价、不调用报价接口。预算同样标注 manual_setting 或 offline_fixture。人工价格不能和演练预算混用。人工协议只覆盖当前首帧／首尾帧基本模型估算；套餐、折扣、额外用量和账户实际账单待核对。

报价绑定整个计划摘要、模型、分辨率、各片段时长、价格版本和金额摘要。整数计算各片段秒数 × 分／秒，总和仍为整数分，不使用浮点金额。有效期取 20 分钟与价格有效期较早者；不适配模型／参数或价格缺失返回 unavailable/null。计划未确认或来源过期时可查看估算，但禁止确认准备。检查素材时重用 inspect_target，不编译 Base64、不保留完整 Prompt。

预算为本地全项目共用的一套当前单次／日／月上限，明确不是账户全站额度。准备时在共享锁内比较全部有效准备分配与上限；单次不超过日上限，日不超过月上限。按 Asia/Shanghai 计算日／月，保存准备时所属日期。降低预算至本日／月已分配额度以下拒绝；版本改变使旧准备条件失效，但不会自动解除旧分配。不存在预算时显示 null，不私自给默认人民币额度。

本轮分配字段 planning_held_minor 与实际消费分开；actual_charged_minor=null、real_money_reserved=false。它只限制本地准备数量，不构成平台预留或收费授权。跨日后当前日分配重新统计，旧准备保留原期间；将来执行前必须重新进行当前期间预留及费用确认，不能直接沿用旧分配。当前月统计本地本月有效准备，不包含模型平台其他项目或历史真实账单。

## 素材审核与准备确认

逐计划审核请求必须带 expected content_hash，分别确认素材使用权、非敏感范围和仅境内处理；任何否认仍保存审核记录，但不允许准备。记录只有计划摘要、确认项与时间，不保存授权文件、原文、真人信息或备注。审核是本地操作者声明，未做法律或平台独立认证。用户应先通过既有计划与受控媒体地址看素材，再确认；整个计划摘要包括固定提示词、参数及素材版本，任一变化须重新审核。

同计划最新审核为当前依据，后来的否认会使旧批准失效。prepare 请求绑定报价摘要、预算 ID、审核 ID、幂等 request_id，并显式 preparation_only=true；服务器重新检查当前价格／预算／审核、报价时效、计划确认／来源、图片字节与协议，全部通过后原子保存准备与额度分配。一个报价最多关联一条准备；同 request_id 同请求返回原记录，不重分配，冲突 409。

准备状态只为 prepared／cancelled，提交次数永远 0、无平台任务编号、不排队，不接入 SIM 或真实传输。GET 只读并动态返回 local_preparation_ready、blockers 与 execution_blockers；已失效但未取消的准备仍占原分配，不能自动释放。cancel 带 expected_revision，仅取消尚未外发的本地准备、释放本地分配，保留完整历史，重复取消幂等，不删除数据。不存在重新打开已取消记录的接口；需要新报价和新的请求编号。

planning_held_minor 保留原始分配快照，取消后不擦除；视图的 active_planning_held_minor 取消后为 0，预算合计只计算 prepared 状态。

## API 合同

沿用 /api，严格拒绝未知字段、布尔金额、负金额、无效 ID、虚假执行参数；错误为统一 error.code/message 与现有兼容 detail，不回显输入／堆栈。所有写接口为本地记录写入，不调用外部服务。

| 接口 | 请求／响应 |
| --- | --- |
| POST /api/wan-prices；GET /api/wan-prices/{id} | 模型、来源、两档分／秒、到期时间；201／200 版本与是否当前，独立认证 false |
| POST /api/wan-budget-policies；GET /api/wan-budget | 来源、三项整数分上限、preparation_only；201 版本；200 当前上限、本日／月分配与可用额度，缺失为 null |
| POST /api/generation-plans/{id}/sample-reviews；GET /api/wan-sample-reviews/{id} | 计划摘要与三项确认；201／200 审核、是否当前、接受与否 |
| POST /api/wan-quotes；GET /api/wan-quotes/{id} | plan_id；201／200 固定估算、摘要、时效及条件 |
| POST /api/wan-preparations；GET /api/wan-preparations/{id} | 报价／摘要／审核／预算／request_id／preparation_only；201／200 持久化准备与条件 |
| POST /api/wan-preparations/{id}/cancel | expected_revision；200 取消记录和已释放本地分配 |

主要错误：422 格式不符；404 记录不存在；409 版本／摘要变化、时效、未审核／未确认、额度不足、幂等冲突；503 存储损坏或写入失败。future schema、重复字段、缺字段、非法关系和链接均保留原文件并安全失败。只有价格／预算／审核均通过也不意味着可执行：真实执行、传输、认证、实际计费仍是固定阻塞项。旧预检中的真实价格未配置提示指向尚未形成可执行真实报价，历史报告不因新记录而改写。
