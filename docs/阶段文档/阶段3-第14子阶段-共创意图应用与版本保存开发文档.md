# 共创意图应用与版本保存开发文档

日期：2026-10-05。顺序：本文件先落盘，再开发、验证、证据和本地提交，不推送。

## 范围与前端适配声明

承接第 13 子阶段。用户选择已确认且依据未变化的请求，在同页人工填写所选字段的新文字，预览前后差异和需核对的镜头，逐次勾选保存确认，再把正文、版本与请求关联一起保存。模型继续后置，不调用供应商，不生成媒体、不新增费用。沿用现有文字字段、影响提示和版本页视觉样式，不迁移已有数据、删除功能或替换技术栈。

一次请求只能应用一次；其他字段及非文字资产保持。已应用请求显示关联版本，后续撤回请求不会回退已经保存的正文；回退仍使用现有文字版本页并单独预览确认。未确认、已撤回、依据过期、项目运行中均禁止应用。保留要求由用户核对，确定性代码保证只改选定字段，不能代替对文字含义的业务判断。

## 接口契约

已有共创 GET、请求 POST、决定 POST 的返回结构保持。新增 `/api/project/{project_id}/co-creation/applications`：GET 返回 `{workspace, revisions, applications}`，共创和文字工作区在同一锁内读取。关联视图包含 application_id、顺序、intent_id、version_id、created_at、request_id；不输出内部摘要。

`POST .../applications/preview` 接收 `{expected_token, intent_id, value}`，新文字最多 10,000 字，可明确清空；不接收客户端指定阶段、路径或整篇替换。服务器从已确认意图定位唯一字段，校验当前正文和确认依据，返回 `{intent_id, expected_token, preview_token, revision}`，revision 为现有文字预览结构。预览不写入业务文件。

`POST .../applications` 额外要求 preview_token、32 位 request_id、严格布尔 acknowledged=true；返回 `{application_id, version_id, data}`。预览摘要绑定共创 token、请求、填写文字和实际修改预览，保存前重新计算。相同请求编号和完全相同提交幂等找回；跨操作或不同内容复用编号拒绝。409 变化、422 非法输入／未确认／已应用／无变化／超限、404 缺失、503 存储异常；统一 error.code/message，兼容 detail，无内部异常或正文泄漏。

## 持久化与兼容

现有 co_creation schema_version=1 增加默认空 applications 数组，兼容旧文件不写回迁移。每个项目最多 100 个应用，计入原 2 MiB 共创账本；文字和历史沿用 2 MiB／32 MiB 限制。关联必须指向本项目的已确认请求与 edit 版本，版本修改只能等于该请求的原字段，修改前值必须等于原值。请求、决定和应用编号全局唯一。损坏或外部修改不覆盖。

复用文字版本的纯准备逻辑，补齐已有未归档正文基线后创建 edit。正文、历史、应用关联通过一次原子会话文件替换落盘，写入前同时比较磁盘旧文字、历史和共创账本；失败全部回滚内存。保存回复丢失后按 request_id 读取关联找回，不自动重发。进程重启后从文件恢复。旧编辑、回退和导出入口保留关联。

## 界面与验证计划

应用面板在选定请求下方，显示原文、新文、影响、逐次确认与已保存版本链接。重新编辑文字使预览和勾选失效。保存中防止重复点击和离开；有未提交文字或预览时切换请求、刷新依据、离开链接需明确放弃；页面卸载后迟到响应不得更新其他项目。失败保留输入并暂停保存，明确重新读取，不自动再写。已应用请求以关联版本为准显示保存结果，正文后来变化也不伪装成待执行请求。

自动化覆盖两种阶段、单字段保持、确认闸门、预览篡改、并发、幂等、跨项目、读写失败、原子回滚、损坏关联、旧数据兼容与重启。真实浏览器人工样例走完整闭环，检查断网／回复丢失找回、输入保护、已保存撤回、四宽度；HTTP 实际重启比较会话和响应，原保护数据不变。独立演练命令 co-creation-apply-demo，默认 8010，前端 3010；样例明确人工，不冒充模型。
