# 阶段 3 第 3 子阶段：项目素材与版本管理

2026-10-05。本文先于代码形成，按产品经理“先文档、再开发、验证后提交”的授权实施。

## 目标与范围

用户从已有项目进入素材页，创建文字素材或上传图片／视频，查看版本历史，选择明确版本用于项目或已有分镜位置；刷新与重启后保留素材及引用。

本轮包含项目素材路由、首页／工作台入口、卡片检索、文字新建与追加、媒体上传归档及追加、预览／下载、版本选择、使用位置与引用历史。可显式导入项目已有角色／场景文字及已选媒体产物，复用原接口。全部素材可人工选入项目，不自动跨项目更新。

模型、付费执行、任务中心、时间轴、自动导出、素材删除、账号与上线不在本轮。旧六阶段产物与 selected 保持，引用选择仍属于生成前准备，不宣称已影响原有生成入口。

## 页面与用户流程

路由 `/projects/[projectId]/assets`，URL 查询参数 asset／version 保存查看位置。入口为首页每个项目卡的“素材与版本”，以及六阶段顶栏；可返回项目工作台。

沿用深色视觉，页头显示项目故事与素材统计，工具栏提供项目／全部素材、分类和搜索；列表与详情在桌面并列，小屏上下排列。详情默认查看最新版本，同时标示实际引用版本，避免混淆。空库引导“新建文字素材”或“上传媒体”；读取失败显示重新读取，不冒充空库。

1. 打开项目素材页，读取项目状态、全库和本项目引用；项目素材由引用及来源项目确定。
2. 新建角色／场景／道具文字，或上传媒体。保存为本地资产后按页面明确动作加入本项目；如果加入失败，说明素材已保存、项目引用未确认，可在全部素材重新选择。
3. 选择素材及历史版本预览。文字修改后追加版本；媒体可上传新文件追加。旧版本、其他项目引用及原成片保持。
4. 查看实际使用位置，明确选择某版本，点击加入项目／引用到已有片段或镜头。切换已有引用前展示原版、目标版和影响，确认后提交；并发冲突重新读取。
5. 刷新或重启后打开原 URL，恢复版本和引用。未提交编辑离开前提示；保存结果不确定时先重读，写请求不自动重发。

## 接口契约

所有失败沿用 `{"error":{"code","message"},"detail":"兼容字段"}`，不返回堆栈、原路径或用户文件正文。

| 方法与路径 | 请求／响应 |
| --- | --- |
| GET /api/project/{id}/status | 项目状态、参数与既有 artifacts |
| GET /api/assets | 全库 Asset 列表，含 versions、source、可选 media |
| POST /api/assets | kind=character/setting/prop、name 1–100 字、definition 1–10000 字；Asset，201 |
| POST /api/assets/{id}/versions | name、definition；追加文字版本，Asset，201 |
| POST /api/assets/import-script、import-media | 沿用项目／阶段／条目合同；Asset，200 |
| POST /api/project/{project_id}/assets/upload（新增） | multipart file、name、definition、upload_id（32 位十六进制）；可选 asset_id，追加到同类媒体资产；Asset，201 |
| GET /api/project/{id}/asset-references | 本项目 ReferenceView 列表 |
| GET /api/assets/{id}/usage | 跨项目实际使用位置与版本 |
| POST /api/asset-references | project_id、asset_id、version_id、可选 segment_id／shot_number；ReferenceView，201 |
| PATCH /api/asset-references/{id} | version_id、expected_revision；ReferenceView，200 |
| GET /api/assets/{id}/versions/{version}/media | 已校验归档二进制；保留 nosniff、private/no-cache 和摘要 |

上传只接收真实 JPG/JPEG、PNG、WebP、BMP（10 MiB、4000 万像素）或 MP4（100 MiB）；扩展名、真实内容与可选声明类型一致。拒绝路径、控制字符或过长文件名，归档采用服务端随机文件名。分块限额、落盘、复用 Pillow／ffprobe 校验和私有媒体发布；异常清理本次未提交临时文件，不删除历史或用户源文件。

新增 upload 来源只记录 project_id、upload_id，不记录原文件路径。幂等编号在库内唯一：同编号、同项目／目标／内容返回原版本；参数或内容不同返回 409。追加媒体与文字版本均不更新既有引用。复用文件锁及原子写入，不新增数据库／依赖。

错误涵盖 404 项目／素材／目标不存在，409 类型／幂等冲突或引用并发冲突，413 大小／像素超限，415 格式不符，422 参数不合规，503 持久化／校验工具／文件完整性异常。

新集中 API 模块统一处理超时、安全错误和运行时结构校验，读请求约 20 秒、媒体写请求约 120 秒，均不自动重试。既有非幂等文字写入在结果不确定后提示先核对已保存版本；上传保留原幂等编号。项目切换、卸载和读取顺序变化不得覆盖新项目状态。

Next.js 同源 rewrites 补齐 assets 与 asset-references 路径，不新增 Proxy 中间层。实测当前版本在外部 rewrites 也会将请求体截断到默认 10 MiB，导致大视频无法提交；补充 `experimental.proxyClientMaxBodySize: '110mb'`，覆盖 100 MiB 视频与 multipart 开销，业务大小仍由后端与前端严格限制。此配置提高单请求缓冲内存，正式多人上线需另评估；本轮仅本机单用户。开发和生产环境均用有效的超过 10 MiB 人工 MP4 验证完整传输，不仅凭配置推断可用。[Next.js 官方说明](https://nextjs.org/docs/app/api-reference/config/next-config-js/proxyClientMaxBodySize)

## 实现与验收

新增 assets 类型／API／纯数据适配函数和业务组件；保留既有目录及集中工作流 API。表单内联呈现减少复杂弹窗；引用切换使用确认对话框，约束焦点、Escape 取消和焦点返回。所有输入关联 label，成功／失败提示有语义；富文本作为普通文字显示，不解析任意 HTML。

归档导入同时兼容现有 reference／video 产物阶段别名；来源合同继续使用 reference_generation／video_generation，不修改旧产物。

自动回归保留全部 522 后端、49 前端测试；新增重点为上传真实格式／大小／文件名、幂等及并发、旧引用不变、提交失败清理和旧库兼容，以及前端合同校验、分类／项目过滤、镜头目标与请求不重发。运行根 `python3.12 scripts/project.py check`。

真实浏览器在人工非敏感项目中跑通建档、追加文字、上传 PNG／MP4、媒体追加、预览／下载、明确引用升级／回退、刷新和实际后端重启恢复；核对原用户会话哈希与旧库记录保持。检查四种宽度、手机菜单、空／错／冲突和保留输入。人工文件明确为本地测试素材，不冒充模型结果。

## 风险与回退

当前仅本机单用户；跨项目使用不等于跨用户授权。多人上线前另做后端隔离。旧 API 没有删除资产或撤销引用接口，本轮不伪造删除按钮。新来源为兼容扩展，旧库无需迁移；如果回退页面，保留当前后端及所有库／媒体，禁止用旧程序覆盖包含新来源的数据。归档的无引用孤立副本清理与磁盘配额另行设计。

## 浏览器检查后的体验补充

窄屏选择素材后自动将详情带入视野，避免点选后停在列表而看不到结果；1000px 以下将列表与详情上下排列。详情与表单保留顶部导航避让。

素材页页头使用透明背景，单独覆盖旧全局 header 的导航背景规则，避免出现无意的灰色矩形；公共顶栏保持原有样式。手机表单截图采用完整可操作的视口，避免全页截图中粘性顶栏覆盖列表。

剧本导入的存储定义保留完整 JSON 用于追溯；页面以名称、描述及中文字段展示业务内容，编辑时预填易读文字。保存后形成独立的新文字版本，原导入记录完整保留。手动填写的 JSON 文本按原文展示；未知字段用“其他设定”保留其内容，不静默丢弃。
