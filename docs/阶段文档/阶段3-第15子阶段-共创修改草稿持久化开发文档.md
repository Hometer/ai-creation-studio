# 共创修改草稿持久化与恢复

日期：2026-10-06。承接第十四子阶段，先本文件，再开发、验证、证据和本地 Git 提交，不推送。

## 范围与前端适配声明

在已确认、依据有效且尚未应用的共创请求下，人工填写新文字，明确点“保存修改草稿”。保存仅写草稿，不改变正文、文字版本、请求确认、媒体或任务；保存后刷新／重启／重新选择该请求可恢复最近草稿。模型继续后置，无新增费用或平台。沿用同页样式、现有文字预览与正式版本保存，保留旧功能及数据。

每次草稿保存形成独立历史，最多每项目 200 条，计入现有 2 MiB 共创账本；每条文字最多 10,000 字，允许明确清空。旧草稿保留，不添加删除操作。未确认、撤回、已应用、旧依据、项目执行中禁止新存草稿，但原草稿继续查看／复制。恢复草稿不恢复预览勾选，不自动应用；正式保存仍需基于当前正文重新预览、逐次确认。

## 数据与接口契约

co_creation v1 增加默认空 drafts 数组。草稿记录为 draft_id、number、intent_id、value、text_token、created_at、request_id、request_digest；编号连续，请求编号在请求／决定／应用／草稿内唯一，草稿引用必须对应本项目请求、确认时序及原 text_token。缺 drafts 的旧文件只读兼容，不写回迁移。旧接口响应结构保持，草稿不加入旧共创视图／应用视图；共创 token 包含完整草稿账本，阻止旧窗口覆盖。

新增 `GET /api/project/{project_id}/co-creation/drafts` 返回 `{data, drafts}`，data 沿用同锁读取的共创／文字／应用工作区，drafts 是不含 request_digest 的视图列表。

同地址 `POST` 接收 `{expected_token, intent_id, value, request_id}`，不接收客户端阶段、路径、整篇替换或执行授权；返回 `{draft_id, result}`，result 同上述 GET。保存先校验确认与当前依据，再原子写入草稿账本；比较磁盘旧账本、正文、文字历史，失败回滚内存。正文及文字历史不变。相同请求编号、完全相同内容幂等返回已有草稿；不同内容或跨操作复用编号拒绝。旧草稿可读取，保存响应丢失先按 request_id 读取找回，不自动重发。

404 缺失，409 token／编号冲突／正在执行，422 未确认／已应用／非法内容／上限，503 存储不可用；统一 error.code/message，兼容 detail，不回显内部异常或请求正文。

## 页面状态与保护

加载请求时默认载入该请求最近已保存草稿。显示“草稿已保存”或“有未保存的修改”，按钮与正式保存明确区分。草稿保存后旧预览及勾选失效，正文不变。有已保存草稿时可重新载入；若当前输入不同，先明确放弃本页未保存输入。重新读取发现另一窗口的新草稿时保留当前输入，并提示手动载入，不能静默覆盖。

导航提示只针对尚未保存的文字和待确认写入；已保存草稿可以离开，返回后恢复。预览是临时结果，离开后重新计算；不会恢复为执行授权。保存中锁定重复点击／切换／离开，页面卸载后迟到响应不能更新其他请求。错误保留输入并暂停写入，重新读取草稿和关联核对；没有自动重试。旧依据／撤回／已应用草稿只供查看，不冒充可继续执行的候选。
