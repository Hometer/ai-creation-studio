# 阶段 3 · 第 1 子阶段：现有前端体验升级

日期：2026-10-05。基线 11c96ab。用户本轮明确模型后置，先调研、方案／文档、开发、验证后提交。本文与技术适配声明、设计方案均先于代码。

## 目标和范围

用户进入有作品感的首页，挑选灵感并编辑故事，将其保存为真实项目草稿，之后从项目区打开并恢复。升级 HomePage、AppShell、TopBar／BrandHeader、全局设计变量、首页历史状态和草稿保存接线。保留既有上传、模型配置、六阶段、流水线、工作台、恢复及删除功能。

不新增模型接入、社区／会员、画布、资产管理页面、时间线或上线。模型相关入口保留为原有功能，不以漂亮页面宣称真实生成可用；本轮验收不发送生成请求。

## 用户流程

1. 首页看到主创作输入与灵感封面，选择下方分类或样例；点击只回填文本并聚焦。
2. 修改文本／剧集／风格等参数，点击保存创作草稿；保存过程中禁用重复提交，失败保留输入并显示错误。
3. 保存成功后看到“我的项目”记录，打开项目；从顶栏确认当前阶段和配置。草稿仅 pending，没有假进度或假产物。
4. 刷新及服务重启后通过项目 URL 恢复；返回首页从项目区继续。管理／删除仍需明确确认，验证不删除既有业务数据。

## 接口契约

沿用 API，不改后端：GET /api/sessions 返回会话列表；GET /api/config 与现有模型清单为公开配置来源；POST /api/project/start 接收 ProjectParams，返回 session_id、status、params，仅创建持久化项目；GET /api/project/{id}/status 返回经现有解析器校验的完整状态；DELETE 会话与现有上传、SSE 均保留原合同。错误由既有统一 API 层处理，不输出堆栈、完整文档或密钥。

新增前端草稿包装显式 expand_idea=false、web_search=false，只调用 startProject，不执行任何 stage、continue 或模型 SDK。普通创建请求不自动重试；未知提交结果不自动重复创建。草稿保存与生成分开，网络异常提醒先查看项目列表再决定重试。列表重试是只读请求。请求与状态处理集中于现有 API／WorkflowPanel，不在视觉组件散落新地址。

## 实现与设计

采用方案中的深色＋黄绿动作强调，复用六张本地封面。增加轻量灵感元数据和筛选辅助模块、草稿包装；不迁移目录、不加依赖。全局 CSS 对旧页面的浅色 utility 做有界兼容，并保持成功／警告／错误语义，不能一概覆盖为主色。首页顶栏区分锚点与页面路由，项目区按钮使用语义控件。

输入 textarea 有 label，中文输入法不会触发提交，Ctrl／Command+Enter 只保存草稿。弹窗与抽屉包含焦点约束，图标按钮有名称，触控最小 44px，focus 清晰，遵守减少动画偏好。手机重排首屏封面与工具卡，配置表单和阶段横向滚动限定在组件内，页面无意横向滚动为失败。
