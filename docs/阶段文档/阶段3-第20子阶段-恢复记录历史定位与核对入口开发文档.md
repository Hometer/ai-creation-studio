## 前端适配声明

沿用 Next.js 16.3.8、React 19、TypeScript strict、既有深色样式和原生控件。目标是让创作者从持久恢复记录找到当时的文字版本、恢复前后差异和需要人工核对的镜头。复用现有原子 GET import-restores、GET compare、GET reviews 与人工核对保存协议，不引入依赖、平台、迁移或费用。模型继续后置；既有范围、预算、留存和账号待定项保留，不影响本机人工切片。

适配现有 Node 单元测试体系，真实页面使用 ego-browser。URL 保存恢复编号、版本编号和对比选择，不保存正文、上传文件或授权。恢复历史定位是只读操作；既有逐次恢复／回退／人工核对确认保持。

## 范围与流程

文字版本页增加恢复历史导航；每次记录可明确选择，刷新／前进后退恢复位置。显示恢复来源、时间、变化阶段、历史版本及是否仍是当前。每个变化阶段定位本地版本；恢复前版本为该阶段严格早于恢复结果的最近版本，与后端 validate_restores 的摘要校验规则一致。支持同页只读定位和直接进入两版对比，保持未保存编辑、文件、预览和勾选。版本列表及详情标注备份恢复出处，不修改原版本 source 枚举。

核对入口带 version 参数，仅显示该次修改的事项，默认全部状态，已核对事项也可找到。未知、重复或损坏参数明确报错，不能悄悄回落到另一版本／全部事项；清除范围是明确动作。返回文字页保留恢复位置。核对仍读取当前目标与当前依据，历史成功记录不表示当前已审核；无影响事项时明确说明仍需自行检查文字及媒体。

本轮不导入历史、不新增自动审核／重生成、不做完整项目恢复、媒体关系恢复、付费模型或上线账号隔离。

## 状态、契约与保护

| 情况 | 展示与行为 |
| --- | --- |
| 加载 | 显示读取中，不提前显示无记录 |
| 空 | 已成功读取后显示无恢复记录 |
| 选择／刷新／返回 | 按唯一 restore 参数找记录，缺失或格式错误明确提示 |
| 记录与页面依据不一致 | 保留旧记录，标记待重新读取；禁止历史定位／对比／核对链接 |
| 读取失败 | 保留旧记录，标记未核实；不把失败冒充空记录 |
| 同页定位／对比 | 更新 URL 和只读位置，不替换编辑输入，不请求恢复或保存 |
| 保存中／回复待核对 | 历史操作锁定；先按既有入口查回恢复结果 |
| 历史版本 | 明确区分当时结果与当前文字，核对结论由现有后端确定 |
| 核对范围未知或参数错误 | 保留范围错误，暂停核对保存，需明确重新选择范围 |
| 核对草稿 | 沿用切换、离开、重新读取确认；不静默丢弃 |

GET `/api/project/{id}/content-revisions/import-restores` 返回 `{workspace,restores}`，后端原子读取并校验恢复前后摘要和版本关系；前端严格检查记录与工作区绑定。GET compare 绑定 expected_token 和同阶段两个版本，409 提示重读；GET reviews 返回完整事项与来源，前端按真实 version_id 限定展示。全部错误沿用 error.code/message，超时20秒，无自动写重试。既有接口结构保持，原文件只读，无新持久字段。
