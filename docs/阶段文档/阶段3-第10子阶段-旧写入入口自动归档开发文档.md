# 旧写入入口自动归档开发文档

日期：2026-10-05。先形成本文，再开发；本轮为阶段 3 第 10 子阶段工程切片，不代表整个阶段验收。

## 目标与范围
旧通用产物补丁及工作流正常生成／介入完成后，剧本与分镜的持久变化自动追加至现有文字历史。用户在文字版本页查看完整快照、差异、镜头影响，并沿用预览确认恢复与人工核对。只有真实保存成功才出现版本，保持旧请求和响应兼容。

模型继续后置。离线代理和人工 HTTP 样例明确标注，不调用供应商；不新增费用、执行入口权限、自动重制作、账号、云服务或完整共创。现有媒体、预算、引用、计划、人工记录保留。

## 实现约定
1. 在引擎的原子保存处增加显式归档选项，由通用补丁、工作流结果提交及携带文字快照的持久化进度启用。旧数据读取、初始化样例、纯进度、状态、参数保存不产生版本；工作流待人工确认的续写预览也属于已保存产物，记录其快照，但不表示确认或执行授权。
2. 同一引擎锁内读取已持久化的原产物与历史，先归档缺失的原阶段基线，再为本次发生变化的剧本／分镜追加 external 来源版本；来源展示为“原入口更新归档”。同时改变两个阶段时一并写入同一会话文件。与已归档末版相同的内容不重复；无变化的补丁不增加版本。
3. 沿用 schema_version=1 与 baseline/external/edit/restore，不增加客户端必须支持的枚举。完整字典快照、类型敏感差异、前后镜头影响并集、时间和摘要使用现有实现。归档不为非字典旧结构做迁移，原接口按现有规则处理，转换时不伪造原结构的字典版本；文字编辑页仍明确不支持非字典结构。支持字典按现有 2 MiB／500 字段／32 MiB 历史上限保护，超限拒绝整次写入。
4. 手动编辑与恢复已有原子历史，不启用二次归档。存在旧未追踪内容时，先保存现有快照再追加本次变化，无法补回接线前每次中间修改。读取历史不写入数据。
5. 缓存文字或历史与磁盘不一致时拒绝旧写入；长任务提交对照最近成功的本任务快照，代理修改输入不能改变此对照，损坏或未来版本数据不覆盖。文件写入失败恢复内存中的原产物、历史与状态；错误遵循现有安全结构，SSE 以 error 收尾。
6. 自动版本带镜头影响，沿用人工核对清单和失效判断；归档不替代人工决定、不变更已生成媒体选择及候选、不激活计划或任务。原入口已有的跨阶段描述／时长同步继续保留，不能把它误写为全部产物元数据完全不变。

补充检查发现原分镜代理逐集持久化 assets_preview，已将其真实文字快照纳入本轮；已归档快照不重复，最终提交从最近成功快照比较。纯进度不写文字版本。
